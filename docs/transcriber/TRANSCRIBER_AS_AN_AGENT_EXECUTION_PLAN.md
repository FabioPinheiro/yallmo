## Recorded decisions and review

1. **Separate session, automatic ID:** the user accepts a session per transcription and asks whether it needs one/a name. Artifacts themselves do not require sessions, but current public writes do. Reuse that API with a collision-resistant safe ID (`transcription-<uuid>`); no user-supplied name or new sessionless-write API. Store human-authored redacted audio as root and transcription-agent assistant text as its child. Do not change the active chat session/head/context. Normal session listing remains unchanged.
2. **Future hash-based debug:** create [DEBUG_BY_MESSAGE_ID_PLAN.md](DEBUG_BY_MESSAGE_ID_PLAN.md). Do not implement new lookup syntax or a transcription debug section in this migration. Keep all existing rendering/export/provider-capture paths audio-safe. Do not resume or inject a transcription session into chat merely to inspect it.
3. **Local configuration authorized:** update `yallmo.json` and secret-free examples during implementation, adding an explicit transcriber reference, prompt/model, and empty capability allowlists. Preserve existing chat settings, endpoints, credentials, and unrelated fields. An existing OAI provider/model may be explicitly configured as the initial choice, but endpoint/model audio acceptance remains unverified until tested; never use selected-chat settings as a runtime fallback.

Review result: the decisions preserve fresh single-turn inference and durable transcript retention without broadening this migration into generic sessionless storage or a new debug UI. The source plan's former requirement to connect retained transcriptions to `/debug` has been replaced with the explicit future-work boundary.
